# Sprint Pulse — Sprint Health & Workload Insights for Azure Boards

**Know the true state of your sprint in seconds.** Sprint Pulse adds a dedicated hub to Azure Boards that turns raw work item data into a clear, actionable view of sprint health, team workload and delivery risk — with zero configuration and no external services.

## Why teams choose Sprint Pulse

- **Sprint Health Score** — a single 0–100 indicator that combines completion progress, blocked work, stale items and unassigned work, so you can tell at a glance whether the sprint is on track, needs attention, or is at risk.
- **Team Workload Balance** — a stacked view per team member showing done, in-progress and not-started items, making overloaded and idle contributors immediately visible.
- **Risk Detection** — automatically surfaces work items tagged *Blocked*, active items with no state change for 7+ days, and open items nobody owns.
- **Delivery Metrics** — completion percentage, story points delivered, remaining work hours and days left in the sprint.
- **State Distribution** — see exactly where work is accumulating across your workflow.
- **One-Click CSV Export** — share sprint snapshots with stakeholders in seconds.
- **Multi-Team Aware** — switch between any team in the project without leaving the page.
- **Process Agnostic** — works with Agile, Scrum, CMMI and inherited custom processes, using the workflow state categories defined in your project.

## Built for security and simplicity

- Runs entirely inside Azure DevOps. **No data ever leaves your organization.**
- Read-only access to work items and project metadata (`vso.work`, `vso.project`).
- No servers, no agents, no accounts, no pricing tiers.
- Fully browser-based, so it works identically for every user on **Windows, macOS and Linux**.

## Getting started

1. Install the extension into your Azure DevOps organization.
2. Open **Boards → Sprint Pulse**.
3. Pick a team. That's it.

To flag a blocker, simply add the tag **Blocked** to a work item. It will appear in the *Needs attention* list immediately.

## Requirements

- Azure DevOps Services (cloud) or Azure DevOps Server with extension support.
- A team with a current sprint (iteration) configured.
